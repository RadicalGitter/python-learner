# Reference review: Coddy's beginner Python lessons

Reference pages reviewed on 2026-09-01:

- <https://coddy.tech/learn/python/fundamentals/hello_world>
- <https://coddy.tech/learn/python/fundamentals/input>
- <https://coddy.tech/landing/python>

The interactive browser was unavailable during this review. The observations
below come from Coddy's publicly rendered lesson content and syllabus, not from
a signed-in click-through session.

## What Coddy does well

### One concept per lesson

The Hello World lesson explains only `print()`, quotation marks, and exact
capitalisation. The Input lesson introduces only `input()`, storing its value,
and the fact that input begins as text. This makes the next action obvious.

### A rapid learning loop

The visible sequence is concise:

1. identify the lesson and its place in the course;
2. explain the concept in a few sentences;
3. show one runnable example;
4. state one small challenge with an exact expected result;
5. provide the editor and Run action;
6. finish with a short quiz and clear previous/next navigation.

The learner reaches code before the explanation becomes tiring.

### Explicit instructions and output

Challenges use short numbered steps and show the precise output expected. This
reduces accidental difficulty: the learner's effort goes into Python rather
than deciphering an assignment.

### Projects are sliced into stages

Larger projects are not single intimidating briefs. The expense tracker, for
example, is spread across overview, exiting, adding, viewing, calculating,
clearing, and error-handling stages.

## Where Python Reboot was weaker

- The first exercise introduced functions, parameters, lists, loops, strings,
  and tests at once.
- The permanent three-column workspace competed for attention before the
  learner understood the task.
- Chapter-level projects were visible, but lesson-level pacing was vague.
- The tutor occupied a whole panel even when the learner had not asked for help.
- “Run tests” was the first action, although a beginner should first experience
  simply running a working program and seeing output.

## Changes we will adopt

- Five-to-ten-minute concept bites, each with one primary idea.
- One worked example followed immediately by one small change.
- Exact, plain-language completion criteria.
- A two-part lesson surface: explanation and editor/output.
- Contextual help collapsed behind “Need a nudge?” until requested.
- Visible lesson position and previous/next movement.
- Chapter projects divided into independently completable stages.

## Choices we will keep distinct

- No streak loss, currencies, leaderboards, or pressure mechanics.
- Projects remain the organising spine; concept bites exist to unlock their next
  stage rather than becoming a 200-item checklist.
- Reflection and code-reading remain completion evidence alongside automated
  checks.
- Returning programmers can reduce guidance without switching to a separate
  curriculum.

## Tempo contract

Most concept lessons should take 5–10 minutes:

1. **See it** — roughly 90 seconds.
2. **Run it** — one click on working code.
3. **Change it** — one deliberate edit.
4. **Check it** — one to three transparent checks.
5. **Say what changed** — one optional reflection prompt.

Project stages should take 20–35 minutes and combine no more than two recently
introduced concepts with familiar material.
